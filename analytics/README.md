# Нечто: исследовательский центр

Аналитика по партиям в «Нечто»: кто во что играл, кто кого в чём подозревал, кто
был прав и у кого какая статистика побед. Отдельный пакет монорепы со своим
бекендом (bun), витриной (vite), админкой и базой (SQLite + drizzle).

Витрина рассчитана на публичный домен: сводная статистика полностью
обезличенная, а страницы по конкретным никам можно одним переключателем в
админке спрятать за псевдонимами.

## Как это устроено

```
игра (src/server)                    аналитика (analytics/)
┌───────────────────────┐            ┌────────────────────────────────┐
│ Game.analytics        │            │ POST /api/ingest               │
│  MatchRecorder        │  партия    │   -> drizzle -> SQLite         │
│  копит события        ├───────────►│                                │
│  в памяти всю игру    │  целиком   │ GET /api/overview|players|...  │
│                       │  и только  │   <- витрина (vite, ванильный  │
│ Game.end() -> sink    │  в конце   │      TS, графики на SVG)       │
└───────────────────────┘            └────────────────────────────────┘
```

**Партия уезжает наружу только после окончания.** Пока за столом идёт игра, в
аналитику не уходит ничего: иначе публичный сайт стал бы читом — по ролям
сразу видно, кто Нечто. Если отправить не удалось, партия лежит в очереди, потом
в спул-файле (`ANALYTICS_SPOOL`), и её можно залить руками через админку.

Аналитика **не имеет права мешать игре**: рекордер молча глотает свои ошибки,
отправка асинхронная, а без `ANALYTICS_URL` она просто выключена.

## Что считается

**Статусы** — главное. В игре каждый может повесить на соседа метку: «чист»,
«под вопросом», «заражён», «Нечто». Каждая простановка записывается вместе с
правдой на тот момент — кем цель была **в эту секунду**, а не в конце партии.
Поэтому «чист», поставленный до заражения цели, считается верным: игрок был прав.

- «Нечто» верно только про само Нечто;
- «заражён» верно про любого заражённого (Нечто в том числе);
- «чист» верно про незаражённого;
- «под вопросом» и снятие статуса мнением не считаются.

Статус выбирается **прокруткой**: конкретную метку в игре не поставить, её
перебирают нажатиями по кружку соседа (`чист → ? → заражён → Нечто → снят`), и
каждое нажатие отдельным событием улетает на сервер. Путь до нужного статуса
мнением не является, поэтому серия нажатий по одной цели схлопывается в одну —
ту, на которой игрок остановился: статус считается выбранным, когда по этой цели
**10 секунд ничего не нажимали** (`MARK_SETTLE_MS`, `src/db/markRows.ts`).

Ждать эти секунды в игре не нужно — интерфейс отзывается мгновенно, а тишину
аналитика видит «задним числом», уже в готовой партии. У записи поэтому стоит
настоящее время и ход того самого нажатия, а не момент, когда истёк бы таймер.

Сырые нажатия целиком остаются в `events`; таблица `marks` — это уже вывод из
них, и её можно пересобрать заново кнопкой «Пересчитать статусы» в админке
(тогда же применятся изменившиеся правила, другое окно и слияния ников).

Кроме статусов пишутся: розыгрыш каждой карты и её цель («сыграл Анализ на X»),
обмены (и передача «Заражения!»), отказы от обмена, паники, карантины,
заражения с источником, смерти с причиной и тем, кто сжёг, решения в диалогах,
ходы и добор карт.

Из этого считаются: победы сторон, победы по ролям, выживаемость, точность
подозрений — общая, по итоговым мнениям и **отдельно по каждому типу метки**
(в досье игрока: где именно он ошибается — в «чист», в «заражён» или в «Нечто»),
матрица «кто кого
подозревал», кого чаще всех обвиняли зря, сколько заражений кто передал, и
титулы («Шерлок», «Параноик», «Козёл отпущения», «Мясник», «Герой Антарктики»…).

### Огнемёт — отдельно

Единственное необратимое действие в игре, поэтому у него своя страница и своя
ручка `/api/flamethrower`. Каждый выстрел получает приговор по **ролям на момент
выстрела**:

| Приговор | Когда |
|---|---|
| `correct` — попал | чистый человек сжёг заражённого или само Нечто |
| `wrong` — ошибка | чистый человек сжёг чистого: минус союзник |
| `byPlan` — по плану | стрелял заражённый или Нечто |

Выстрелы заражённых «правильностью» не судим: сжечь своего ради алиби и чужого
ради победы одинаково осмысленно, ошибкой это не является.

Тот же приговор выносится попыткам, которые отбили «Никаким шашлыком» — спастись
от верного выстрела и от ошибочного это разные истории. Поэтому в движке
спасение пишется отдельным событием (`card_play` c `noFire`, где actor —
спасшийся, target — стрелявший): иначе половина выстрелов не имела бы исхода.

Считается: всего выстрелов / сожжено / отбито и доля спасений, разбивка по
приговору отдельно для сожжений и для спасений, сколько раз сожгли само Нечто,
на каком ходу стреляют, по каждому стрелку (выстрелы, попадания, ошибки,
точность, сожжённые Нечто), по каждой мишени (сколько раз целились, сожгли,
отбился, сожгли зря) и пары «кто в кого». Выстрелы, у которых не нашлось исхода
(партию бросили между выбором цели и решением), показываются отдельной строкой,
а не приписываются к спасениям.

Партии с ботами в общую статистику **не идут** — они разделены полем `source`,
и по умолчанию витрина показывает только `live` (переключатель источника есть в
шапке). Партии тестов и e2e игровой сервер не отправляет вообще.

## Запуск

```bash
./run analytics migrate     # создать/обновить базу
./run analytics seed        # демо-партии, чтобы витрина не была пустой
./run analytics server      # бекенд на :3200
./run analytics web         # витрина на :5174 (проксирует /api на :3200)
```

Или в докере — профиль `analytics`. `./run go` поднимает его вместе с игрой;
`./run up` (только игра) — нет:

```bash
./run analytics up
./run analytics logs
```

Через туннель витрина живёт на `${ANALYTICS_HOST_PUBLIC}`, её API — на
`${ANALYTICS_API_HOST}`. Сайту второй хост не нужен (фронт ходит в `/api`
относительным путём через прокси vite), он для прямых запросов к API.

Сборка витрины: `./run analytics build` → `analytics/dist/web`. На проде тот же
bun-сервер отдаёт и API, и собранную витрину, так что публичный домен достаточно
направить на него одного.

## Окружение

| Переменная | Где нужна | Зачем |
|---|---|---|
| `ANALYTICS_URL` | игровой сервер | Куда отправлять партии. Пусто — аналитика выключена |
| `ANALYTICS_TOKEN` | обе стороны | Общий секрет приёма партий. Пусто — приём запрещён |
| `ANALYTICS_ADMIN_TOKEN` | аналитика | Пароль админки. Пусто — админка выключена |
| `ANALYTICS_DB` | аналитика | Путь к SQLite (по умолчанию `analytics/data/analytics.sqlite`) |
| `ANALYTICS_PORT` / `ANALYTICS_HOST` | аналитика | Где слушать (3200 / 0.0.0.0) |
| `ANALYTICS_SPOOL` | игровой сервер | Файл для партий, которые не удалось отправить |
| `ANALYTICS_WEB_DIR` | аналитика | Откуда отдавать собранную витрину |
| `ANALYTICS_MARK_SETTLE_MS` | аналитика | Окно «прокрутки» статуса, мс (по умолчанию 10000) |
| `ANALYTICS_HOST_PUBLIC` | витрина | Публичный хост за туннелем (для vite/HMR) |

## API

Публичное (только чтение, CORS открыт):

```
GET /api/meta                 заголовок, источники, итоговые счётчики
GET /api/overview             обезличенная сводка: победы, карты, точность
GET /api/players              рейтинг игроков
GET /api/players/:key         досье игрока (key — ник в нижнем регистре)
GET /api/awards               титулы
GET /api/matrix               матрица подозрений
GET /api/matches              список партий
GET /api/matches/:id          разбор партии: роли, события, лог
```

Общие фильтры: `?source=live|bots|e2e|test|all`, `&bots=true`,
`&incomplete=true`, `&from=`, `&to=`, `&minMatches=`.

Приём партий: `POST /api/ingest` с `Authorization: Bearer $ANALYTICS_TOKEN`,
тело — `{version, matches: [...]}`. Идемпотентно по `matchId`.

Админка (`Authorization: Bearer $ANALYTICS_ADMIN_TOKEN`): статистика базы,
скрытие/удаление партий, скрытие и переименование игроков, **склейка двух ников
в одного человека**, пересчёт статусов, обезличивание витрины, дамп и импорт
спула.

## Миграции

Схема живёт в `src/db/schema.ts`, миграции генерирует drizzle-kit:

```bash
./run analytics generate      # после правки схемы
```

Сгенерированный SQL лежит в `analytics/drizzle/` и накатывается автоматически при
старте сервера — отдельного шага деплоя не нужно.
